## 8. Analisis MSI: Gap Tata Kelola Informasi PUBDEKDOK

### Menggunakan Kerangka Lima Unsur Sistem (Bu Ratna):

| Unsur | Kondisi PUBDEKDOK saat ini | Status |
|:---|:---|:---|
| **Input** | Foto/video dari HP pribadi, permintaan desain via WA mendadak | Ada, tapi tidak terstandarisasi |
| **Proses** | Desain di Canva/CapCut, dokumentasi manual | Ada, tapi bergantung pada satu orang |
| **Output** | Poster WA group, konten Instagram (saat masih bisa), file di flashdisk | Terbatas dan tidak berkelanjutan |
| **Manpower** | Fajar (utama) + Mas Kurniawan (fotografer) | **Key-person dependency** ekstrem |
| **Teknologi** | Semua perangkat dan akun pribadi — tidak ada aset teknologi resmi milik masjid | **Tidak ada teknologi institusional** |

### Menggunakan Kerangka Resource → Capability → Value:

```
RESOURCE (ada):
  - Kamera Mas Kurniawan
  - Canva/CapCut Fajar
  - Flashdisk Fajar
  - Drive pribadi Fajar

CAPABILITY (tidak terbentuk dengan baik):
  - Tidak ada sistem penyimpanan bersama
  - Tidak ada SOP produksi & distribusi konten
  - Tidak ada regenerasi SDM yang mau mengambil peran
  - Platform distribusi (Instagram) tidak fungsional

VALUE (tidak tercapai secara berkelanjutan):
  - Transparansi visual kegiatan: TIDAK KONSISTEN
  - Arsip institusional: TIDAK ADA
  - Peningkatan partisipasi jamaah: TIDAK TERUKUR
```

### Masalah Inti (Root Cause — Lensa MSI):

Bukan masalah tidak punya kamera bagus.
Bukan masalah tidak bisa desain.

Masalah sesungguhnya adalah **ketiadaan tata kelola informasi** di level PUBDEKDOK:
1. Tidak ada **SOP** untuk siklus kerja PUBDEKDOK (dari permintaan → produksi → distribusi → arsip)
2. Tidak ada **RACI** yang jelas (siapa Responsible, Accountable, Consulted, Informed untuk setiap konten)
3. Tidak ada **platform institusional** — semua berbasis aset pribadi yang tidak dapat diwariskan
4. Tidak ada **mekanisme regenerasi** — jika Fajar tidak aktif, PUBDEKDOK berhenti
5. Tidak ada **prosedur handover** untuk akun digital yang sudah dibuat

## 9. Rekomendasi Minimal (Zero-Cost, Human-Centric)

Berdasarkan prinsip MSI (bukan sekedar digitalisasi), solusi yang tepat konteks:

| Masalah | Rekomendasi | Biaya |
|:---|:---|:---|
| File tersebar di HP pribadi | Buat 1 folder Google Drive bersama (shared), semua anggota wajib upload pasca-kegiatan | Gratis |
| Akun Instagram tidak bisa diakses | Recovery akun via email Gmail masjid, tambahkan minimal 2 admin | Gratis |
| Gmail masjid akses tidak jelas | Audit akses, transfer ke admin resmi yang ditunjuk takmir | Gratis |
| Permintaan mendadak | Buat SOP sederhana: notif PUBDEKDOK minimal H-3 untuk desain, H-1 untuk dokumentasi | Gratis |
| Key-person dependency Fajar | Rekrut dan latih minimal 1 anggota REMAS baru sebagai kader PUBDEKDOK | Gratis |
| Tidak ada penunjukan resmi | Masukkan nama-nama PDD ke dalam SK atau catatan resmi takmir | Gratis |

> **Catatan:** Semua rekomendasi di atas adalah masalah **tata kelola dan SOP** — bukan masalah yang membutuhkan aplikasi baru atau pembelian teknologi. Ini konsisten dengan prinsip MSI Bu Ratna: solusi teknologi tanpa tata kelola = motor tanpa jalan dan SIM.
